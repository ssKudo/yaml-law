法令データのパースと構造化

e-Gov Law APIから取得したオリジナルのXMLから、RAGフレンドリーな構造への変換例です。

● e-Gov 生XML (変換前)

ネストが深く、機械的なチャンク分割では関係性や見出し情報が欠落しやすい構造。

article_001.xml
<!-- e-Gov Law XML -->
<Article Num="1">
  <ArticleTitle>第一条</ArticleTitle>
  <ArticleCaption>（目的）</ArticleCaption>
  <Paragraph Num="1">
    <ParagraphNum/>
    <ParagraphSentence>
      <Sentence>この法律は、建築物の敷地、構造、設備及び用途に関する最低の基準を定めて、国民の生命、健康及び財産の保護を図り、もつて公共の福祉の増進に資することを目的とする。</Sentence>
    </ParagraphSentence>
  </Paragraph>
</Article>
  • タグ情報が多くトークンが無駄になる
  • 条文同士の参照リンクがテキストに埋もれて解決できない

● 本データセット (変換後)

メタデータ、本文、リンクエッジに役割を分離。タブを切り替えて構成を確認できます。 

law_id: "325AC0000000201"
law_title: "建築基準法"
law_num: "昭和二十五年法律第二百一号"
part: "本則"
chapter: "第一章 総則"
article_num: "1"
article_title: "第一条"
article_caption: "（目的）"
description: "国民の生命、健康、財産を保護するため、建築物の敷地・構造・設備・用途に関する最低基準を定めた法律。"
text_path: "../texts/article_001.txt"
  • 高速スキャン: 軽量YAMLでインデックス走査が可能
  • 本文の切り出し: `text_path` から本文のみをクリーンにロード
  • 関係性の自動拡張: リンクグラフを介して他の条文と接続

⚠️ 設計上の制約（弱点）と実運用での解決策

本データセットを実際のRAGシステムで効果的に運用するためのポイントと開発推奨アプローチです。

■ 制約1：検索漏れ（表現の不一致）

本データセットは「メンテナンス性」と「取り回しの良さ」を最優先した結果、YAMLに概要・キーワードを持たせる構成にしています。しかし、ユーザーの質問文とYAML内のキーワードが完全一致しない場合、検索から漏れてしまう弱点があります。

💡 推奨解決策：「クエリ拡張」の導入
ユーザーの自然言語での質問からRAG検索クエリを生成する際、事前に「クエリ拡張（類義語・同義語・定義語の展開）」の処理を検索エンジン側に組み込むことを強く推奨します。

■ 制約2：機械生成メタデータの網羅性

各条文の概要（description）およびキーワードは、LLM（Gemini 3.5 Flash）を用いて機械的に自動生成しています。そのため、要約が不十分であったり、一部の重要キーワードが抜け漏れている場合があります。

💡 推奨解決策：フィードバックループ型の運用
膨大な法令すべてを手動で整備するのは非現実的です。まずは本リポジトリで一括生成したデータをベースに運用を開始し、実際のチャット応答や検索ログから「ヒットしなかったキーワード」を特定してピンポイントで追加・更新していくサイクルを推奨します。

AIツール・開発への導入方法

AIエージェントにそのまま読ませることも、ご自身のPython RAGプログラムに統合することも非常に簡単です。

CodexCLI / Claude Code / Antigravity IDE (2.0) 
💡 **AIエージェント（CodexCLI, Claude Code, Antigravity IDE など）への読み込ませ方**

本データセットは「1条文＝1ペア（YAMLメタデータとTXT本文）」に分割され、条文参照リンクグラフも事前構築されているため、AIエージェントに読み込ませるだけで最高のパフォーマンスを発揮します。

1. **リポジトリをローカルにクローン**
   `git clone https://github.com/ssKudo/yaml-law.git`
   
2. **各エージェントでの活用方法**
   - **CodexCLI / Claude Code**: 
     クローンしたディレクトリを作業領域（Cwd）としてコマンドラインから指示を出します。AIエージェントは軽量なYAMLメタデータをスキャンして該当条文の `text_path` を即座に特定し、必要な本文TXTファイルのみをロードするため、トークン消費を最小限に抑えつつ高速に回答を生成します。
   - **Antigravity IDE (2.0)**: 
     プロジェクトフォルダとしてワークスペースを開くだけです。AIアシスタントがフォルダ構造および `data/links/article_links.yaml`（リンクグラフ）を自動認識し、複雑な法令のQAやコード生成を高精度に実行します。

**効果**: 1条文ごとに綺麗に分割されているため、AIが関係のない条文データまで過剰に読み込む（コンテキストを圧迫する）ことがなく、法解釈の混乱やハルシネーションを防ぎます。
